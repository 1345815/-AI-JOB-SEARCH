# 08 · 管理后台与运营洞察改进提示词

## 🩺 根因诊断

| 坑 | 当前表现 | 排查命令 |
|---|---|---|
| 无 admin 角色 | `users.role` 字段存在但只写入 `guest`/`user`，admin 从未被赋值 | `grep -n "role" web/server.py`（`:246`、`:2398`、`:536`） |
| 无管理 API | 没有任何 `/api/admin/*` 路由，运营方无入口 | `grep -n 'head == "admin"' web/server.py`（无结果） |
| 前端已预留 | `app.js:262` 已处理 `user.role === "admin"` 显示「管理员」，但无对应后台页 | `grep -n "admin" web/static/js/app.js` |
| 运营不可见 | 用户数、任务失败、存储占用、活跃度无任何聚合视图 | `curl -s localhost:8000/api/...`（无 overview 端点） |
| 无用户治理 | 无法查看/停用/提权用户，guest 僵尸号无法清理 | `web/server.py:1858` 所有 API 仅校验「已登录」 |

**最常见组合**：① + ② + ③ —— 角色体系、API、前端三处都要动，才能形成闭环。

# 目标
为这个纯标准库的单进程 HTTP 服务（web/server.py）补齐企业级运营视角：
1. admin 角色体系：首个注册用户自动成为 admin；后续 admin 可通过环境变量 CAREERPILOT_ADMIN_USERNAME（逗号分隔用户名）指定
2. 管理 API：/api/admin/overview（运营总览）、/api/admin/users（用户列表与治理：停用/启用/设为/撤销 admin）
3. 前端管理页：侧边栏「管理」入口（仅 admin 可见），展示运营总览卡片 + 用户表格 + 治理操作

# 你必须新增/修改的内容
1. 修改 web/server.py：
   - init_db()：给 users 表加 `disabled INTEGER DEFAULT 0` 列（走 :405 的 PRAGMA+ALTER 模式）
   - 新增 helper：`is_admin(user)`、`list_users(limit, offset, query)`、`set_user_disabled(user_id, disabled)`、`set_user_role(user_id, role)`、`admin_overview()`
   - admin_overview() 返回：用户总数、7 日活跃用户数（sessions/help_records/applications 最近 7 天有活动）、岗位总数、申请总数（按 stage 分组）、任务总数与失败数、DB 文件大小、LLM 是否启用
   - register（:2376）：若 users 表当前用户数为 0，或 username 在 CAREERPILOT_ADMIN_USERNAME 环境变量列表中，role 置为 'admin'
   - _api() 新增分支（在 :1858 用户校验之后）：
     - GET /api/admin/overview → admin_overview()
     - GET /api/admin/users?limit=&offset=&q= → 用户列表（不含密码哈希，含 disabled 标志）
     - PATCH /api/admin/users/<id> → body: {"action": "disable"|"enable"|"set_admin"|"remove_admin"}，禁止操作自己（id==当前用户）
   - 所有 /api/admin/* 先校验 is_admin(user)，非 admin 返回 403 {"ok": False, "error": "需要管理员权限"}

3. 修改 web/static/js/app.js：

   - 新增治理操作函数：调 PATCH /api/admin/users/<id> 后刷新列表
   - titles 对象加 `admin: "运营管理"`
