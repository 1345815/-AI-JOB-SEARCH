# 10 · 留存触达与跟进提醒改进提示词

## 🩺 根因诊断

| 坑 | 当前表现 | 排查命令 |
|---|---|---|
| 字段存在无触达 | applications 表有 `follow_up_at`、jobs 有 `deadline`，但无任何读取提醒逻辑 | `grep -n "follow_up_at" web/server.py`（仅字段定义/写入，无查询提醒） |
| 无「今日待办」聚合 | 每日推荐只有 2 个岗位，无「今天该跟进谁、谁快截止、谁要准备面试」的清单 | `grep -n "daily-recommendations" web/server.py`（`:1882` 仅返回 2 个岗位） |
| 无通知中心 | 站内没有任何「提醒/通知」表或视图，用户回访无抓手 | `grep -n "notification" web/server.py`（无结果） |
| 无截止日倒计时 | deadline 只是字符串，无「距截止 N 天」的紧迫感呈现 | `grep -n "deadline" web/static/js/app.js`（仅展示，无倒计时） |
| 留存无抓手 | 用户 3 天不回访，产品无法召回 | 无任何主动触达能力 |

**最常见组合**：① + ② + ③ —— 先做「今日待办」聚合 API + 站内通知表，倒计时与召回基于它们才成立。

## 📋 提示词正文（整段复制给 AI Agent）

```text
请在当前工作区（AI-JOB-SEARCH 仓库根目录）实施「留存触达与跟进提醒」。你是资深全栈工程师，只做本任务，不做无关重构。

# 目标
为这个纯标准库的单进程 HTTP 服务（web/server.py）建立「让用户每天回访」的能力：
1. 今日待办聚合 API：/api/today-tasks — 返回四类提醒（今天要跟进的申请、7 天内截止的岗位、待准备面试的岗位、待处理的收藏）
2. 站内通知表 notifications：应用内产生提醒时落表，用户可读可标记已读
3. 前端「今日待办」区块：dashboard 顶部聚合展示，每条可一键跳转对应页面
4. 通知中心：顶栏铃铛图标 + 下拉通知列表（未读数徽标）
5. 截止日倒计时：岗位卡片与详情页显示「距截止 N 天」（红/黄/绿三档）

# 你必须新增/修改的内容
1. 修改 web/server.py：
   - init_db() 新增：
     CREATE TABLE IF NOT EXISTS notifications (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       user_id INTEGER NOT NULL,
       type TEXT NOT NULL,
       title TEXT NOT NULL,
       body TEXT DEFAULT '',
       link TEXT DEFAULT '',
       read INTEGER DEFAULT 0,
       created_at REAL NOT NULL,
       FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
     );
     CREATE INDEX IF NOT EXISTS idx_notifications_user_read ON notifications(user_id, read);
   - 新增 notify(user_id, type, title, body, link)：插入通知
   - 新增 today_tasks(user_id)：返回 dict，四类：
     - follow_ups: applications WHERE stage IN ('已投递','面试中') AND follow_up_at <= 今天（按 follow_up_at 升序，取前 10）
     - deadlines: jobs WHERE deadline BETWEEN 今天 AND 7 天后（按 deadline 升序，取前 10）
     - interviews: applications WHERE stage='面试中'（取前 10）
     - pending: applications WHERE stage='已收藏'（取前 5）
     - 每项含 {id, title, company, stage, deadline, follow_up_at, days_left}
   - 新增 notifications 相关 helper：list_notifications(user_id, limit)、mark_notification_read(user_id, notif_id)、unread_count(user_id)
   - 在关键动作处产生通知（每处调用 notify 一行）：
     - 岗位 deadline 距今 <=3 天时，在打开岗位详情时若未读过该 job 的通知则生成「岗位即将截止」
     - follow_up_at 当天，登录后首次加载 today-tasks 时生成「今天该跟进 XX」通知
     - 申请 stage 变为「面试中」时生成「XX 进入面试阶段，准备起来」
   - _api() 新增：
     - GET /api/today-tasks（登录）→ {"ok": True, "data": today_tasks(user_id)}
     - GET /api/notifications?limit=20（登录）→ {"ok": True, "data": [...], "unread": N}
     - POST /api/notifications/<id>/read（登录）→ 标记已读
     - POST /api/notifications/read-all（登录）→ 全部已读

# 约束
- 通知是「尽力而为」：notify() 失败静默，不得影响业务主流程
- 不引入第三方依赖；不引入邮件/SMS/推送（本阶段只做站内）
- 通知生成需防重复：同一 job 的「即将截止」通知每条 job 只生成一次（可用 link 去重：SELECT 1 FROM notifications WHERE user_id=? AND link=?）
- 不改动既有 API 返回结构，只新增
- 日期比较统一用 YYYY-MM-DD 字符串比较（deadline 是 TEXT）；days_left = (deadline - today).days
- 前端沿用 esc()/api()/toast()/el() helper
```
