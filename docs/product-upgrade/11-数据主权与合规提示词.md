# 11 · 数据主权与合规改进提示词

## 🩺 根因诊断

| 坑 | 当前表现 | 排查命令 |
|---|---|---|
| 无法导出 | 用户数据（档案/岗位/申请/简历/聊天/文档）无任何批量导出 API | `grep -n "export\|/api/data" web/server.py`（无结果） |
| 无法注销 | 无账号删除接口；注册后数据永久驻留 | `grep -n "delete" web/server.py`（仅 jobs/会话，无用户级） |
| 无隐私政策 | 登录页/设置无「隐私政策」「数据说明」入口 | `grep -n "隐私\|privacy" web/static/index.html`（无结果） |
| 无数据清理策略 | 无「自动删除 N 天前的游客数据」机制，guest 僵尸数据累积 | `grep -n "guest_" web/server.py`（`:552` 只建号，无清理） |
| 无审计 | 管理员操作（停用/提权）无留痕 | 无 admin_action_log 表 |

**最常见组合**：① + ② —— 导出与注销是合规底线，优先做；清理策略与审计随后补。

## 📋 提示词正文（整段复制给 AI Agent）

```text
请在当前工作区（AI-JOB-SEARCH 仓库根目录）实施「数据主权与合规」。你是资深后端工程师，只做本任务，不做无关重构。

# 目标
为这个纯标准库的单进程 HTTP 服务（web/server.py）补齐数据合规能力：
1. 个人数据导出 API：/api/export — 打包当前用户的档案、岗位、评估、申请、简历、聊天、文档、事件为 JSON 下载
2. 账号注销 API：/api/auth/delete-account — 级联删除该用户全部数据（含 sessions/events/notifications）
3. 隐私说明：登录页与设置页加「隐私与数据说明」文案（数据存哪、如何删除、如何导出）
4. 管理员操作审计表 admin_actions：admin 的停用/提权等操作留痕（依赖 08 的 admin 接口，若已实施）
5. 游客数据清理脚本：scripts/cleanup_guests.py — 删除超过 N 天未活跃的 guest 账号及其数据

# 你必须新增/修改的内容
1. 修改 web/server.py：
   - init_db() 新增：
     CREATE TABLE IF NOT EXISTS admin_actions (

   - 新增 delete_user_data(user_id)：事务内删除该用户全部关联数据 + 用户本身（SQLite 外键级联兜底，但仍显式 DELETE 关键表保证兼容无外键模式）

   - 可被 cron/systemd timer 调用；输出删除数量统计

# 约束
- 导出响应绝不含 password_hash、api_key；简历二进制内容只导出文件名与元信息（不内嵌文件内容）
- 注销是硬删除（非软删除），执行前必须二次确认（前端 confirm + 后端 confirm 字段）
- delete-account 禁止删除 admin 账号（返回 403「管理员账号不可注销，请先转移权限」）
- 不引入第三方依赖；不用 zipfile 也行——导出直接 JSON，前端 Blob 下载
- 清理脚本默认 --dry-run，必须显式加 --commit 才真正删除
- 不改动既有 API 返回结构，只新增
```
