# 09 · 求职漏斗与产品埋点改进提示词

## 🩺 根因诊断

| 坑 | 当前表现 | 排查命令 |
|---|---|---|
| 无事件表 | 用户行为（搜索/评分/生成/投递）散落在各业务表，无统一事件流 | `grep -n "CREATE TABLE" web/server.py`（无 events 表） |
| 转化不可度量 | 无法回答「100 个岗位里多少被收藏、多少投递、多少进面试」 | 无漏斗聚合函数/API |
| 埋点无入口 | 业务代码里没有统一的「记录用户行为」调用点 | `grep -n "record_event\|track(" web/server.py`（无结果） |
| 前端无漏斗 | 用户和管理员都看不到转化视图 | `grep -n "funnel" web/static/js/app.js`（无结果） |
| 活跃度靠猜 | 7 日活跃只能靠 sessions/help_records 间接推断 | 无 events 时间分布 |

**最常见组合**：① + ③ —— 先建事件表与埋点函数，漏斗 API 与前端视图基于事件流才能落地。

## 📋 提示词正文（整段复制给 AI Agent）

```text
请在当前工作区（AI-JOB-SEARCH 仓库根目录）实施「求职漏斗与产品埋点」。你是资深数据工程师 + 全栈工程师，只做本任务，不做无关重构。

# 目标
为这个纯标准库的单进程 HTTP 服务（web/server.py）建立「可度量的产品转化」：
1. events 事件表：记录用户关键行为（job_searched / job_scored / job_saved / applied / interview_scheduled / offer_received / resume_generated / cover_letter_generated / interview_prep_generated / chat_sent / daily_recommendation_viewed）
2. 埋点函数 record_event(user_id, event_type, payload)：业务代码中在关键动作处调用
3. 漏斗 API：/api/funnel（当前用户自己的转化漏斗）与 /api/admin/funnel（管理员看全局，依赖 08 的 admin 校验）
4. 前端漏斗视图：岗位搜索页顶部或独立区块展示「岗位 → 评分 → 收藏 → 投递 → 面试 → Offer」漏斗图（纯 CSS/JS 条形漏斗，不引入图表库）

# 你必须新增/修改的内容
1. 修改 web/server.py：
   - init_db() 新增：
     CREATE TABLE IF NOT EXISTS events (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       user_id INTEGER NOT NULL,
       event_type TEXT NOT NULL,
       payload TEXT DEFAULT '{}',
       created_at REAL NOT NULL,
       FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
     );
     CREATE INDEX IF NOT EXISTS idx_events_user_time ON events(user_id, created_at);
     CREATE INDEX IF NOT EXISTS idx_events_type ON events(event_type);
   - 新增 record_event(user_id, event_type, payload=None)：INSERT，payload 用 json.dumps
   - 新增 funnel_stats(user_id=None)：按 event_type 分组 COUNT，返回 {event_type: count}；user_id=None 时统计全局
   - 在以下位置埋点（每个调用一行，payload 保持轻量，禁止放敏感字段）：
     - jobs search POST（:2005）：record_event(user_id, "job_searched", {"keywords": 前20字})
     - score_job 首次保存（save_evaluation 内）：record_event(user_id, "job_scored", {"job_id": job_id})
     - applications 新增（找 _api 里创建 application 的位置）：record_event(user_id, "job_saved")
     - applications stage 更新为「面试中」：record_event(user_id, "interview_scheduled")
     - applications stage 更新为「Offer」：record_event(user_id, "offer_received")
     - tasks 提交 resume.generate/cover_letter.generate/interview.generate（:2082-2093）：对应 record_event
     - assistant_reply（:1436）：record_event(user_id, "chat_sent")
   - _api() 新增：
     - GET /api/funnel（登录即可）→ {"ok": True, "funnel": funnel_stats(user_id)}
     - GET /api/admin/funnel（admin 校验，参照 08）→ {"ok": True, "funnel": funnel_stats()}
2. 修改 web/static/js/app.js：
   - 岗位搜索页（renderJobs 顶部）或 dashboard 新增「我的求职漏斗」区块：6 级条形漏斗（岗位评分→收藏→已投递→面试中→Offer），数值来自 /api/funnel
   - 每级条宽按比例（最多 100%），数值显示在条尾；无数据时显示空状态引导
   - 新增 loadFunnel() 并在 renderJobs/renderDashboard 中调用

# 约束
- events 表只增不改：不提供 DELETE/UPDATE 事件 API（审计完整性）
- 埋点不得拖慢主流程：record_event 失败必须静默（try/except 吞掉），不得影响业务响应
- payload 禁止包含 api_key、password、简历/聊天完整内容（只允许 job_id、keywords 摘要、task_type 等轻量字段）
- 不引入第三方依赖（不用图表库，漏斗用 CSS 条形实现）
- /api/funnel 只返回自己数据；全局统计只走 /api/admin/funnel（需 admin）
- 不改动既有 API 返回结构，只新增
```
