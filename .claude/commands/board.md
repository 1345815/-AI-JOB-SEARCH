# /board - 求职行动工作台

生成一个面向行动的本地 HTML 工作台，默认输出到 `reports/job-board.html`。优先运行 `python tools/generate_board.py` 生成基础报表，再按下列规则补充或审阅结果。它读取 `job_search_tracker.csv`、`job_scraper/seen_jobs.json`、`documents/applications/**/outcome.md` 和 `run-manifest.json`，不写入这些数据。

## 首页优先展示

1. **今天优先处理：**
   - 7 天内截止或已过期的岗位；
   - 已起草但尚未提交的申请；
   - 已申请且超过 10 天没有新联系的岗位；
   - manifest 缺失或质量检查有警告的申请。
2. **阶段队列：** 待评估、已匹配、已起草、待提交、已申请、面试、Offer、已结束。
3. **每条记录的下一步：** 使用明确动作文本，例如“打开岗位并运行 `/apply`”“检查 HTML 简历”“准备面试材料”“运行 `/outcome` 更新结果”。只推荐动作，不自动执行投递或发送消息。
4. **数据质量提示：** 显示缺失来源、过期截止日期、无 manifest、异常状态和无法匹配归档的记录。
5. **本地筛选：** 支持按公司/岗位搜索、按状态筛选、按质量状态筛选；点击岗位来源只打开原始 URL，不向外部网站提交任何信息。
6. **材料定位：** 每条记录显示归档中已有的文件名；缺少归档或材料时显示数据质量提示，避免用户在多个目录中手工查找。

生成器的 `--check` 模式会输出 `rows`、`malformed_manifests`、`missing_manifests` 和 `check_warnings`。只有 manifest 格式损坏时返回失败码；缺少旧 manifest 或质量警告属于可修复提示，不阻塞旧数据使用。

## 规则

- 使用 `/html-report` 的状态词汇和 legacy 状态兼容规则，不创建第二套状态模型。
- 计算安静天数时使用 tracker 的 `date` 与 outcome 中最新的带日期记录；`drafted` 不计入安静提醒。
- 排序优先级为：阻塞问题 → 截止日期 → 需要用户确认的材料 → 安静提醒 → 其他。
- 所有岗位标题、公司名、备注和 URL 都必须 HTML 转义；报表必须离线可打开，无外部请求。
- 空数据也要显示清晰的“暂无待处理事项”，不能用虚构的统计填充。

## 输出验收

报告生成后说明输出路径、优先处理事项数量、数据质量警告数量，并提示用户重新运行 `/board` 刷新，不在本命令中修改 tracker 或申请归档。
